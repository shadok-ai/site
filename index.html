what it is

One cockpit for every agent in the company

It starts the way it usually does: a Claude Code session open in one directory, then another, then five — and none of them survive closing the laptop. shadok-ai is the interface around them.

Each agent is a real Claude Code session with its own directory and its own git branch, driven from the browser or from Telegram. You group them the way you group people: a Tech group, a Marketing group, a Support group. Open one and you are in its conversation — the same session, whoever is watching.

they work in parallel

Each one in its own branch, so they never collide

Give an agent a repository and it works in a git worktree of its own: its own checkout, its own branch. Two agents on the same codebase cannot overwrite each other, and you read the diff before anything is merged.

An agent can also start another one, hand it a task, and be told the moment it finishes — or the moment it stops to ask something. Nothing sits polling, and a child that dies says so.

you supervise

A role, a leash, and a question when it matters

A profile is a named role you give an agent at startup: the system prompt it begins with, the model it runs, how hard it is told to think, the secrets it may see, and the commands it may not run. Forbid git commit and it cannot commit. Change the profile on a running agent and it restarts in place, keeping the conversation.

When an agent needs a decision it does not guess: the question arrives as a card with buttons, in the browser and on your phone at once, and the turn waits.

Run it yourself

An agent that asks you to run something gets a run button on the command it wrote. One click, one confirmation showing exactly what will run, straight into that agent's shell — as you, not as the agent.

Every prompt has a name on it

Put a password on the cockpit and each pilot gets a login of their own. Switch on two-factor and the fingerprint or face unlock of your own phone finishes the sign-in; lose it and another admin lets you back in.

Keys live in a vault

Never in the repository. A profile names the secrets its agents need and they arrive as environment variables at startup. Each secret keeps its own history — who created it and which agent it was handed to, names only, never values.

they stop redoing each other's work

A shared ledger, so nobody re-raises what is done

Agents working in parallel re-discover the same bug, re-propose the same fix, re-run the same job. The cockpit keeps one short table of what has been resolved or decided, and every agent is handed what changed before its next message, without asking for it.

One row per subject: a new line on the same subject replaces the old one, so the table stays short enough to read.

while you are away

A schedule, and a check that costs nothing

Give an agent a recurring prompt: every thirty minutes, or every morning at nine in the time zone you name. Attach a one-line shell check and it runs without the model — if the check prints nothing, nothing happened, and the agent is never woken.

A watcher that stays quiet most of the day costs you nothing most of the day.

from anywhere

Answer them from your phone

The cockpit works on a phone screen, and it connects to Telegram: every agent gets its own topic, questions arrive as buttons you tap, files you send land in the agent's working directory, and what it produces comes back the same way.

Speak instead of typing and the voice note is transcribed on the machine shadok-ai runs on, never handed to a transcription service. Send a video and it is watched, not just filed.

It is not a notification feed — it is the same session your browser is watching, so an answer you tap on the train shows up on the screen you left open.

not only code

The same cockpit for the rest of the company

An agent does not have to be a developer. The role you give it decides what it is: one reads the support inbox and tells you which ticket to take first, one rewrites the page nobody has looked at in a month, one watches a deploy.

They share the ledger, the schedule, the vault and the same chat — which is what makes this a cockpit rather than a terminal multiplexer.

what it costs

On the subscription you already pay for

Agents run on your own Claude account, through the claude CLI — no API key, no second bill. The cockpit watches how fast you are spending your five-hour and seven-day windows and holds a prompt back when you are running ahead of an even pace. Any message can push through when you mean it.

Or a model you host yourself

Point the cockpit at Ollama, llama.cpp or vLLM — or at any Anthropic-compatible provider. It is a choice in the first card, and it makes one real round trip to that server before it lets you keep it.

Self-hosted, and yours

It runs on your machine or your own server, on loopback unless you give it a password. Nothing about your repositories, your prompts or your keys passes through anyone else.

It keeps itself current

Every merge publishes a version and a running cockpit picks it up on its own, agents and all. It also warns you two days before your Claude sign-in expires, and signs you in again in one click.

it wrote itself

Most of this was built by the agents it ships

Nearly every feature on this page was written by a shadok-ai agent working in its own worktree, reviewed and merged like any other contribution. The pull requests are public, and so is the history — see for yourself.

why it is called that

Les Shadoks pumped

They were French cartoon birds drawn in 1968, and the whole joke was that they pumped — relentlessly, exhaustingly, and for no result anyone could ever identify. One of their mottos: the more it fails, the more likely it is to work.

An agent woken every hour to report that nothing happened is pumping. You pay a model call to be told there was nothing to do, and it will tell you that twenty-three more times today. This is the tool that lets it stop.
